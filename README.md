# Автотесты виджета поддержки Учи.ру

[![Playwright](https://github.com/Vlad1k22/uchi-aqa-intern-challenge/actions/workflows/playwright.yml/badge.svg)](https://github.com/Vlad1k22/uchi-aqa-intern-challenge/actions/workflows/playwright.yml)

Решение тестового задания для стажировки QA Fullstack.
Исходный проект: [uchiru/aqa-intern-challenge](https://github.com/uchiru/aqa-intern-challenge).
Репозиторий создан отдельно, без fork; история исходного проекта сохранена.

## Подготовка

Нужны Node.js 22 (версия в `.nvmrc`), npm и доступ к `uchi.ru` и `help.uchi.ru`.

```shell
npm ci
npx playwright install chromium
```

В Linux для установки системных библиотек браузера:

```shell
npx playwright install --with-deps chromium
```

## Запуск

```shell
npm run typecheck
npm test
```

Исходная команда `npx playwright test` также работает.

```shell
npm run test:headed
npm run test:ui
npm run test:report
```

Проверка стабильности без retry, по три независимых запуска каждого теста:

```shell
npx playwright test --repeat-each=3
```

По умолчанию тесты открывают `https://uchi.ru`. Для отдельного стенда можно передать
переменную окружения `BASE_URL`. Тесты не отправляют обращения в поддержку
и не требуют входа в аккаунт.

## Сценарии

В проекте ровно три теста: два исправленных исходных и один дополнительный.

| Тест | Что проверяет |
| --- | --- |
| `opens` | Открывается виджет, появляется его содержимое и список популярных статей. |
| `has correct title` | После открытия статьи и перехода к обращению заголовок равен «Связь с поддержкой». |
| `opens the selected popular article` | Дополнительный тест: выбранная популярная статья открывается, её название видно, список статей скрыт и доступна связь с поддержкой. |

Каждый тест получает новый браузерный контекст и начинает с главной страницы.
Порядок выполнения не влияет на состояние других тестов.

В начальном состоянии контекста зафиксирована cookie `ab_mainpage_redesign=a`.
Это выбирает исходный вариант главной страницы, на котором расположен виджет
из задания. В первом прогоне CI вариант `c` открывал `/index_v3` и не загружал
виджет. Фиксация варианта устраняет случайный выбор другой страницы;
ответы сервера и содержимое виджета остаются настоящими. Cookie авторизации
и пользовательские данные не используются.

## Исправления

- Кнопка открытия находится по `data-test="openWidget"`, без зависимости от внешнего компонента типографики.
- Локаторы содержимого ограничены телом виджета, чтобы не находить похожие элементы основной страницы.
- «Написать нам» находится по роли кнопки и точному имени. Исходный селектор `[class^=btn]` совпадал с шестью элементами, включая оценку статьи и вложенный текст кнопки.
- Вместо `Locator.all()` используется локатор первой статьи с ожиданием видимости. Список не считывается до его загрузки.
- Заголовок проверяется через `await expect(locator).toHaveText(...)`, с ожиданием обновления интерфейса.
- Cookie-уведомление обрабатывается, если появляется, включая позднюю загрузку. Скрытая копия уведомления исключена из локатора.
- В Page Object собраны локаторы и действия, а в тестах оставлены сценарии и проверки результатов.
- Удалены неиспользуемые аргументы фикстур, добавлены строгая проверка TypeScript и команды npm.
- Playwright обновлён с 1.50.1 до 1.64.0, включая исправление проблемы проверки сертификатов при скачивании браузеров. Версии зафиксированы в lock-файле.

Фиксированных задержек `waitForTimeout`, `force: true`, пропусков тестов и подмены
ответов сервера нет. Повторные прогоны отключены, чтобы ошибка не скрывалась за retry.

## Отчёты и CI

GitHub Actions запускает проверку TypeScript и все три теста на каждом push,
pull request и ручном запуске. Один worker ограничивает нагрузку на внешний сайт.

HTML-отчёт создаётся в `playwright-report/`. При падении сохраняются скриншот,
trace и описание ошибки в `test-results/`. В CI эти файлы доступны в артефакте
`playwright-report` в течение 7 дней. Локальные отчёты и `node_modules` не включены в Git.

Если сайт возвращает HTTP 403 или виджет не загружается из-за недоступности
`help.uchi.ru`, это видно в отчёте как неуспешный прогон. Такой результат
не заменяется успешной проверкой на заглушках.
